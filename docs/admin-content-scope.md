# PWLIF Admin Content Scope

The current Admin Portal is intentionally limited to content that already has a controlled, server-authorized data model. This protects public visitors, Sponsor Talent privacy, and the Foundation’s ability to avoid accidental publication of unreviewed material.

| Public route or content area | Current Admin Portal control | Current status |
| --- | --- | --- |
| Homepage hero, brand copy, and homepage media placement | Branding controls | Editable |
| Mission & Vision | Mission and Vision controls | Editable |
| Meet the Team | Team controls with per-member visibility choices | Editable |
| Sponsor Talent directory and public detail pages | Sponsor Talent CMS with private-by-default, granular release controls | Editable |
| Talent skills, interests, and categories | Foundation-managed tag and category libraries | Editable |
| Privacy, terms, and security standards | Legal and Security controls | Editable |
| Foundation introduction videos | Foundation Video controls | Editable when a Foundation-approved media URL is available |
| Foundation Updates | No publication model yet | Truthful empty state only |
| Stories & Learning | No publication model yet | Truthful empty state only |
| Media Gallery | No publication model yet | Truthful empty state only |
| Press & Resources | No publication model yet | Truthful empty state only |

The four public update and press routes are deliberately **not editable yet**. They use truthful empty states because PWLIF has not approved an editorial publishing workflow, review status, or public asset-release model for those areas. Making them editable safely would require a dedicated Foundation-managed content model with draft/review/publish states, asset permissions, and an audit trail. That is a separate scope from the secure Sponsor Talent, contact, and sponsor-messaging workflows completed in this repair.

The Foundation Inbox is now operational for public contact submissions and approved-sponsor messages. It is not a public content-publishing tool: administrators can review and mark messages as reviewed, while the original message remains retained for operational follow-up.
